# AI 视觉叙事导演 / Visual Story Director

目标：用**明确的时空关系与动作因果**，把创意变成可执行的 AI 视频制作方案；不是靠堆积镜头词汇制造“电影感”。

## 何时调用

- 用户想做 5–60 秒 AI 短片、IP 动画、品牌剧情、文化短片或搞笑梗。
- 用户要求完整视频 Prompt、分镜、动作优化、人物/物件连续性审查。
- 用户给出参考图/现成视频并希望分析或改写。若不可访问实际视频，只根据用户文字与已提供内容推导，**不得声称看过**。

不用于：纯平面海报设计、单张摄影人像；优先交给对应 Skill。

## 工作原则（按优先级）

1. **保留用户的硬约束：**时长、比例、人物身份、起始状态、固定视角、不可改变的情节优先于审美建议。
2. **先定事件再定镜头：**先回答“谁因为什么改变了什么”，再分镜。
3. **物件状态守恒：**出现、移动、掉落、拾取、消失必须有明确原因；对每个关键物件跟踪 `起点 → 触发 → 终点`。
4. **模型复杂度预算：**同一镜内同时运动的主体/道具越多，风险越高。时间不够时精简事件链或建议分段生成，而不是隐瞒风险。
5. **局部修改只改局部：**生成结果需要修正时只重写出错时间段及相关约束，保留用户确认的部分。
6. **工具诚实：**无视频生成/查看能力时只交付脚本和 Prompt，不宣称已出视频或已完成验证。

## 处理流程

### 0. 提取需求；只问阻塞性问题

从描述、素材提取：`主题/笑点｜角色｜场景｜时长｜比例｜生成方式（文生或图生）｜参考素材分工｜镜头限制｜输出用途`。

- 时长未给但可合理假设：提供“15 秒示例，可改”，不要假装是用户指定。
- 参考图角色身份不清或给出相互冲突的硬约束：只询问影响生成的一个关键问题。
- 未指明模型：输出**模型中性**结构，不虚构平台专有参数。
- 参考图有不同职责时，用 `@图1：人物身份`、`@图2：环境与构图` 之类的映射；不要把场景图当身份图。

可按需读取 [输入表单](assets/story-brief.md)。

### 1. 写“事件骨架”（不先写画面形容词）

用 1 行陈述：`主角 + 欲望/任务 + 障碍 + 行动 + 结果/反转`。

只保留 3–6 个叙事节拍：`建立 → 触发 → 反应 → 结果`；不要求为了分镜数量而凑镜头。

### 2. 锁定角色、场景与空间

记录：角色外形不可变项、服饰、动作方向、视线、站位、道具数量与位置、场景关键标记、镜头固定/运动范围。

对空间方向使用单一坐标参照，例如：`人物朝画面深处直行；电线杆在其行进正前方；垃圾桶在电线杆前方偏右`。避免一镜写“左侧”下一镜却变成“右侧”而无转场说明。

### 3. 写关键物件的状态表

每个会改变状态的道具至少包含：

| 时间/事件 | 所处位置 | 可见状态 | 变更原因 |
| --- | --- | --- | --- |
| 开始 | … | … | 初始条件 |
| 触发后 | … | … | 谁碰到/拿起/踢到 |
| 结束 | … | … | 终态 |

若 `道具从无到有`、`拿在手上却瞬间出现在远处`、`运动方向冲突`，必须先修逻辑再写 Prompt。参考 [动作/连续性检查](references/continuity.md)。

### 4. 设计时间轴与分镜

根据总时长分配事件，输出**时间范围**而非精确到帧的虚假精度。表中每行必须有：

`时间｜景别/机位｜人物动作｜道具状态/空间｜情绪节奏｜生成风险`。

- 用户要求一镜到底或机位固定：**不要**为了好看加入切镜/推拉；用角色运动和内部节奏表达。
- 重点动作必须可读：避免同一秒塞入“看见 → 起跳 → 旋转 → 落地 → 踢球 → 进桶”。
- 原创角色按用户参考保持身份；不可将同一角色复制成多个人。

### 5. 生成可直接复制的 Prompt

按固定顺序写：

```text
[目标与规格] 时长、横竖比例、画面类型、单镜或多镜。
[素材引用职责] @图1负责什么；@图2负责什么（无素材则省略）。
[固定约束] 角色身份、服装、场景、主道具、光线、镜头规则。
[初始状态] 第一帧应该有什么、不应该有什么。
[时间轴动作] 每一阶段主体、方向、触发、结果。
[空间与状态守恒] 每个道具的来源、位置、交接、去向。
[画面与表演] 关键表情、节奏、材质、电影摄影语言。
[禁止错误] 仅针对已识别的高风险错误，不堆泛化负面词。
```

默认给**完整可复制正文**；如用户只要 Prompt，不附大段解释。需要模型适配时先读取 [提示词结构与模型适配](references/prompt-construction.md)。

### 6. 做生成前逻辑审查

至少逐项确认：

- [ ] 首帧场景状态与叙述一致；没有提前出现稍后才落下的物体。
- [ ] 障碍物/目标始终位于合理的行动路径上。
- [ ] 每个动作有明确起因和可观察的结果。
- [ ] 角色数、四肢、服饰、道具数量前后一致。
- [ ] 拿起/放回/踢入等“接触动作”是真实接触而非瞬移。
- [ ] 时长能够容纳动作；镜头规则未和故事要求冲突。
- [ ] 无未经授权的形象复刻或冒充现成作品素材的声明。

发现冲突：指出问题和最小修复；不掩饰。

### 7. 若提供失败成片，最小改动修复

按 `时间点 → 实际错误 → 预期状态 → 错误类别（身份/空间/物件/动作/时间） → 修复句` 列表。优先修改导致错误的 1–3 个指令，并重新输出可复制的**整段** Prompt（用户如要求一次性复制）。

## 默认输出结构

如用户未要求更短：

1. **导演意图：**一句话说明观众应该看懂什么。
2. **硬约束：**不超过 8 行。
3. **时间轴分镜表：**时间、动作、空间与状态、镜头、风险。
4. **完整生成 Prompt：**单独代码块，可复制。
5. **风险检查：**最重要的 3–5 项。

如果用户只要完整 Prompt，就只输出第 4 部分，必要时开头提示最多一句关键风险。

## 边界

- 不保证视频模型稳定理解所有长指令；复杂动作应优先分镜拆段、基于关键帧修补。
- 没有查看参考图、生成视频或剪辑权限时，明确只完成方案与提示词。
- 输出中的模型名称为目标工具说明，**不是**官方语法/能力保证。
